# Machine Learning-Based Classification of TLS Encryption

A machine learning project that classifies TLS network metadata according to a predefined encryption security policy using a Random Forest classifier. The project includes data preparation, policy-based labeling, model training, evaluation, and a Streamlit dashboard.

## Overview

Transport Layer Security (TLS) helps protect network communication through encryption. However, not every TLS protocol version or cipher suite meets a given security policy.

This project uses available TLS metadata to classify records into three categories:

- **Approved** — the observed TLS version and selected cipher suite meet the project's defined policy.
- **Not Approved** — the observed metadata violates a defined policy rule.
- **Unknown** — the metadata is missing or cannot be classified reliably by the policy rules.

The labels are generated using predefined rules informed by NIST SP 800-52 Rev. 2. A Random Forest model is trained to predict these labels from the available metadata.

**Important:** These results represent the project's policy-based classification. They do not prove that an entire TLS connection is secure or fully compliant, and they do not involve decrypting network payloads.

## Objectives

- Analyze TLS metadata without decrypting payload content.
- Define policy-based labels for observed TLS records.
- Train a Random Forest classification model.
- Evaluate model predictions using classification metrics and a confusion matrix.
- Visualize dataset statistics and model results through a dashboard.

## Project Workflow

1. **Dataset inspection:** Examine the available TLS metadata and identify relevant fields.
2. **Policy definition:** Map supported TLS versions and selected cipher suites to project-specific security labels.
3. **Data preparation:** Clean records, handle missing values, and prepare features for machine learning.
4. **Label generation:** Apply the defined policy rules to create target labels.
5. **Model training:** Train a Random Forest classifier on the prepared data.
6. **Model evaluation:** Review accuracy, classification reports, and the confusion matrix.
7. **Dashboard:** Explore dataset distributions, model performance, and predictions through Streamlit.



Streamlit will display a local URL in the terminal. Open that URL in your browser.

## Model and Evaluation

The project uses a Random Forest classifier with categorical feature encoding. Evaluation includes:

- Accuracy
- Classification report
- Confusion matrix
- Comparison of actual and predicted labels

Evaluation results depend on the dataset, label-generation rules, and train/test split. If some classes contain very few records, their reported metrics may not generalize to new traffic.

## Dataset and Policy Notes

The labeled dataset and policy mapping are included in this repository. The original `malware_sample.csv` file is intentionally excluded.

The policy is informed by **NIST Special Publication 800-52 Revision 2**. This is an educational implementation of selected policy rules, not a certified compliance checker. Actual TLS security also depends on factors such as certificate validity, key strength, server configuration, and other protocol details that may not be present in the dataset.

## Limitations

- The model learns labels generated by the project's policy rules; it does not independently prove that an encryption method is secure.
- Missing or unrecognized metadata can prevent reliable classification.
- Duplicate or highly similar records can affect evaluation results.
- A high test score alone does not establish real-world generalization.
- The model evaluates the available metadata rather than decrypting traffic or inspecting plaintext payloads.
